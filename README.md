# FinTrack by Finnet Technologies

FinTrack is a portfolio and transaction tracker for investment analysts. The repository is split into independently runnable `frontend/` and `backend/` applications. The Node.js REST API is the source of truth; the browser mock is an optional development-only mode.

## Project layout

- `frontend/` — React, TypeScript, Vite, Tailwind, React Router, TanStack Query, forms, and API client.
- `backend/` — Node.js/Express REST API, PostgreSQL access, SQL migrations, demo seeder, tests, and OpenAPI specification.
- `backend/migrations/` — versioned database schema.

## Run locally on Windows

Install workspace dependencies from the repository root:

```powershell
npm install
Copy-Item backend\.env.example backend\.env
Copy-Item frontend\.env.example frontend\.env.local
```

Edit `backend\.env` and set `DATABASE_URL` to the **newly rotated** Render connection string, plus a random `JWT_SECRET` of at least 32 characters. For a Render external connection, set `DATABASE_SSL=true`. Never paste database credentials into source files or commit `.env` files.

Apply the SQL migration, seed the demo account, then run both applications:

```powershell
npm run migrate
npm run seed
npm run dev
```

The frontend is served at `http://localhost:5173`, and the API at `http://localhost:4000`. Vite proxies local `/api` requests to the backend. The seed script reads `DEMO_EMAIL` and `DEMO_PASSWORD` from `backend\.env`; the example values provide `analyst@finnet.demo` / `demo1234` for assessment use.

## Render deployment

Create a Render **Web Service** from this repository with:

- Root directory: `backend`
- Build command: `npm install`
- Pre-deploy command: `npm run migrate`
- Start command: `npm start`
- Environment: `NODE_ENV=production`, `DATABASE_URL` from the linked Render PostgreSQL database’s **internal** connection string, `DATABASE_SSL=true`, `JWT_SECRET` generated by Render, and `CORS_ORIGIN` set to the deployed frontend origin.

In the deployed frontend build, set `VITE_USE_MOCK_API=false` and `VITE_API_BASE_URL` to the deployed backend origin (for example `https://your-api.onrender.com`, with no trailing slash). Serve `frontend/` as a static site; set the publish directory to `dist` and the build command to `npm install && npm run build --workspace frontend`. Use HTTPS for both services.

For the demo login on Render, configure `DEMO_EMAIL` and `DEMO_PASSWORD` on the backend, then run `npm run seed` from the backend shell or a one-off job. The seeder upserts the sample user, portfolios, and seeded transactions. Use a unique, assessment-only demo password on any public deployment.

## API

Interactive API documentation: `/api/docs`  
OpenAPI JSON: `/api/openapi.json`  
Health check: `/api/health`

Endpoints include:

- `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/refresh`
- `GET/POST /api/portfolios`, `GET/PUT/DELETE /api/portfolios/:id`
- `GET/POST /api/portfolios/:id/transactions`, `DELETE /api/transactions/:id`
- `GET /api/portfolios/:id/summary`

Portfolio routes require a bearer access token. Passwords are hashed with bcrypt. Transaction writes are wrapped in a PostgreSQL transaction and lock the portfolio row while enforcing sell availability. Portfolio ownership is checked server-side; foreign keys cascade transaction deletion. API errors use `{ "error": { "code": "...", "message": "...", "details": {} } }`.

## Frontend configuration

`frontend/.env.example` selects the backend API by default. To use the optional local demo adapter, set `VITE_USE_MOCK_API=true`. Production frontend builds should set `VITE_API_BASE_URL` to the backend origin and keep the mock disabled.

## Design and demo scope

Light/dark color, surface, border, and status design tokens live in `frontend/src/theme.css`. Dark appearance follows system preference. The sample valuation uses static indicative prices and a fixed KES/USD conversion; it is not live market or FX data. CSV export and internationalisation are out of scope.
